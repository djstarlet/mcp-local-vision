# MCP Local Vision

mcp-local-vision is a single-file Python MCP (Model Context Protocol) server that gives text-only AI agents the ability to describe images using a local llama.cpp vision model. It speaks newline-delimited JSON over stdio and proxies image content to the model's OpenAI-compatible chat completions API — no cloud services, no vision-specific agent configuration.

Use this when you run a local llama.cpp server with a vision-capable model (tested with Qwen 3.5 4B, also works with MiniCPM-V, LLaVA) and want any agent or subagent in opencode to answer "what is in this image?" with one tool call.

## What It Does

Agents call the `vision_describe` tool with a file path and get back a text description generated by the local vision model:

```text
vision_describe("/home/youruser/Pictures/screenshot.png")
→ "The image shows a terminal window running a file manager..."
```

The server handles the entire pipeline: image sanity checks, base64 encoding, the OpenAI-compatible request, and response extraction. The `vision_model` config value is only a label — a single-model llama.cpp server accepts any value.

## Quick Start

1. **Start the vision model.** Run llama.cpp's server with a vision model and its mmproj file:

   ```bash
   ./llama-server -m model.gguf --mmproj mmproj.gguf \
     --host 0.0.0.0 --port 8080
   ```

2. **Clone the repo and create `config.json`** (the file is gitignored; copy the example):

   ```bash
   git clone <repo-url> ~/projects/mcp-local-vision
   cd ~/projects/mcp-local-vision
   cp config.json.example config.json
   ```

3. **Register the server in `opencode.jsonc`:**

   ```jsonc
   "mcp": {
     "local-vision": {
       "type": "local",
       "command": ["python3", "/path/to/mcp-local-vision/server.py"],
       "enabled": true
     }
   }
   ```

4. **Restart opencode.** MCP config is not hot-reloaded.

5. **Call the tool.** Any agent can now run `vision_describe("path/to/image.png")`.

## Configuration

All settings are read from `config.json` in the repo directory, and each one can be overridden with an environment variable. Precedence: **env var > config.json > default**.

| Config key | Env var | Default | Description |
|---|---|---|---|
| `vision_api_url` | `VISION_API_URL` | `http://localhost:8080/v1/chat/completions` | OpenAI-compatible endpoint |
| `vision_model` | `VISION_MODEL` | `OBSERVER` | Model label (any value works for single-model servers) |
| `vision_max_tokens` | `VISION_MAX_TOKENS` | `2048` | Max response tokens |
| `vision_timeout` | `VISION_TIMEOUT` | `180` | API timeout in seconds |

## Subagent Access

Subagents (e.g. `@vision`, `@observer`) need the `mcp` tool group to use MCP tools. Add it to their config:

```jsonc
"<subagent-name>": {
  "model": "...",
  "toolGroups": ["mcp", "read"]  // "mcp" grants MCP tool access
}
```

## Standalone CLI

`describe.sh` sends the same request without the MCP layer — useful for testing the model endpoint:

```bash
./describe.sh /path/to/image.png
```
